# 小嗨猜猜猜 —— 项目规划

> **日期：** 2026-11-25\
> **依据：** `docs/设计文档.md`（v1.1）\
> **目标设备：** iPhone 17 Pro Max，iOS 26.5.1\
> **当前状态：** 连连看已上线；消消乐开发中

------------------------------------------------------------------------

## 1. 目标与范围

**目标：** 做出一个装在 iPhone 主屏幕上、断网可玩的聚会猜词游戏。手机横屏举起、屏幕朝向朋友，屏幕翻向地面算答对，翻向天空算跳过。

**第一版包含：**

-   首页（**选主题**、选时长、音效开关、灵敏度）。
-   游戏流程（就绪检测 → 3-2-1 → 出题 → 翻转判定 → 结算）。
-   翻转识别，以及屏幕按钮兜底。
-   12 个主题的内置词库（日常、歌曲、历史等）加「混合」，跨局不重复。
-   音效和全屏颜色反馈。
-   屏幕常亮、横屏显示（兼容竖排方向锁定）。
-   PWA 安装和离线运行。

**第一版不包含**（放入第 6 节的后续候选）：

-   后端、账号、联机、排行榜。
-   多队伍轮流计分。
-   用户自定义词库。
-   历史战绩。

------------------------------------------------------------------------

## 2. 总体思路

项目的不确定性几乎全部集中在「iOS 网页能不能做到」这一类问题上，而不是游戏逻辑本身。所以顺序是：

1.  **先用一个调试页把所有平台能力一次验证完**（阶段 1）。传感器、屏幕常亮、音效、横屏舞台，任何一项不行都会改变设计，越早知道越好。
2.  **再写不依赖浏览器的纯逻辑并配上单元测试**（阶段 2）。这部分可以在电脑上完成和验证，不需要手机。
3.  **然后把界面接上去**（阶段 3），此时底层已经可靠，界面只是显示。
4.  **最后做 PWA 打包和部署**（阶段 5）。Service Worker 的缓存会干扰开发调试，放在后面接入。

**分工：** 代码、文档和单元测试由 Claude Code 完成。所有需要拿着真实 iPhone 操作的验证只能由你完成，每个阶段都列出了具体要做的事。

### 阶段 1：平台能力验证（已完成，2026-11-25）

只做一个调试页，不做任何游戏界面。

| 任务 | 说明 |
| --- | --- |
| 权限申请 | 点击按钮申请，显示授权结果 |
| 实时数据显示 | beta、gamma、tilt、upX、upY，事件频率 |
| 识别器雏形 | 显示当前状态和最近一次识别结果，带计数 |
| 参数滑块 | 触发角度、保持时间、回正角度可现场调整 |
| 录制与导出 | 录一段姿态数据，复制到剪贴板或下载 |
| 屏幕常亮测试 | 申请 Wake Lock，显示是否成功；静音视频降级开关 |
| 音效测试 | 播放答对 / 跳过音效 |
| 横屏舞台测试 | 一个带文字的舞台，验证两种方向锁定状态下的显示 |
| 错误屏显 | 未捕获的异常显示在页面上 |

**需要你做的事：** 按设计文档 9.1 的 13 个步骤在 iPhone 上逐项测试，把结果告诉我（或把导出的数据贴回来）。其中屏幕常亮一项需要分别在 Safari 和「添加到主屏幕」两种方式下测试。

**出口条件：** 下面每个问题都有明确结论。

| 问题 | 如果结论是「不行」 |
| --- | --- |
| tilt 公式的数值和符号是否符合预期？ | 改用 `devicemotion` 的重力数据；仍不行则回到 v1.0 的校准方案 |
| 翻转过程中 tilt 是否连续、无跳变？ | 同上 |
| 连续 20 次动作的漏判、误判是否可接受？ | 调整参数；必要时加入基准姿态补偿 |
| Wake Lock 在主屏幕 Web App 下是否生效？ | 启用静音视频降级 |
| 静音开关打开时是否还有声音？ | 首页加提示，作为已知限制接受 |
| 开启方向锁定时横屏舞台是否显示正确？ | 调整舞台实现 |
| 每次启动是否都要重新授权？ | 只影响文案，不影响设计 |

阶段 1 结束后，根据结论更新设计文档（确定参数、移除已不适用的降级描述），再进入阶段 2。

### 阶段 2：核心逻辑（已完成，2026-11-25）

实际产出：`game/types.ts`、`game/wordDeck.ts`、`game/gameReducer.ts`（含计时）、`sensor/readiness.ts`（开局就绪检测）、`platform/storage.ts`、`data/themes.ts`（12 个主题，每个先放约 15 个示例词）、词库体检测试。共 105 个单元测试通过。实机录制数据的回放测试暂缺（阶段 1 没有导出录制数据），等有数据后补上。

全部是不依赖浏览器的纯逻辑，全部带单元测试，在电脑上完成。

| 模块 | 内容 | 测试要点 |
| --- | --- | --- |
| `sensor/tilt.ts` | beta / gamma → tilt、upX、upY | 几个标准姿态的数值 |
| `sensor/gestureDetector.ts` | 识别器 | 回放阶段 1 录制的实机数据；一次动作只触发一次；抖动不触发；数据中断 |
| `game/wordDeck.ts` | 洗牌、跨局去重 | 局内不重复；跨局优先未出过的词；出完后重置 |
| `game/gameReducer.ts` | 应用阶段与出题状态 | 每个状态转移；时间到时的未完成词；暂停与恢复 |
| 计时 | 基于截止时间戳 | 暂停期间不扣时间 |
| `platform/storage.ts` | 设置读写 | 数据损坏、版本不匹配时回退默认值 |
| 词库体检 | 检查词库文件 | 无重复、无空串、长度合规 |

**需要你做的事：** 无。

**出口条件：** `npm test` 全部通过。

### 阶段 6：真实聚会验收

找朋友实际玩一次，重点观察：

-   两三米外能否看清词语。
-   翻转动作是否自然，有没有漏判和误判。
-   持机者能否听清音效。
-   连续玩多局是否稳定，有没有黑屏、卡住。
-   词库是否有趣，难度是否合适。

根据反馈调整参数和词库。设计文档第 12 节的验收标准全部满足后，第一版完成。

按预估价值排序，不作承诺：

4.  **词库难度分级。**
5.  **更好的音效和动效。**
