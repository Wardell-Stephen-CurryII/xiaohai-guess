# 小嗨猜猜猜 · 个人资料与 VIP 方案（2026-11-26 定稿）

## Context

用户想给游戏加「用户等级 / VIP」：VIP 可以改名字、选头像、头像框、称号（分级别）、徽章佩戴、装饰、配色。约束（已与用户确认）：

- 不做账号、不起服务器；游戏照常离线可玩。
- 不绑定设备；**激活时必须联网**，到 GitHub（随网站发布的文件）上核对激活码。
- 激活码由作者在朋友打赏后手动发放；作者可以随时作废某个码。
- VIP 只给装饰性的东西，不锁词库和玩法（「永久免费」文案不变）。

## 一、激活码机制（无服务器）

**思路：** 激活码是随机短码，仓库里只公开它的 SHA-256 哈希列表。激活时联网下载列表，比对哈希；作废就是从列表删掉。码本身从不公开，也无法从哈希反推。

- 码格式：`XH-XXXX-XXXX-XXXX`，12 位 Crockford Base32 随机字符（60 位熵，无法穷举）；输入时忽略大小写、空格、横线，`O/0`、`I/1/L` 自动纠正。
- 公开文件：`public/vip/codes.json`，按等级分两组哈希（见第三节）。
- **激活：** 联网 `fetch(BASE_URL + 'vip/codes.json?t=' + Date.now(), { cache: 'no-store' })` → `crypto.subtle` 计算哈希 → 命中则开通，本机保存 `{ code, activatedAt, lastVerifiedAt }`。断网时提示「激活需要联网」。
- **定期核对：** 每次联网启动时后台再查一次；哈希不在列表 → 取消 VIP（提示「激活码已失效，请联系作者」）。超过 **30 天**没核对成功 → VIP 暂停，联网一次即恢复。
- Service Worker 不能缓存这个文件：`vite.config.ts` 的 workbox 加 `globIgnores: ['vip/**']`（现有 `globPatterns` 包含 json）。
- 发布延迟：推送后 GitHub Actions 约 1 分钟上线；GitHub Pages CDN 最多再缓存约 10 分钟（查询参数可绕过大部分缓存）。

**作者工具** `scripts/vip.mjs`（Node，`npm run vip -- <命令>`）：
- `new --tier vip|svip --to 张三 [--note 备注]`：生成码 → 哈希追加到 `codes.json` → 在本地台账 `private/vip-ledger.csv`（`.gitignore` 忽略，不公开）记下 码 / 给谁 / 日期 → 自动 `git commit` + `push`，打印激活码，复制发给朋友。
- `revoke <码或名字>`：从 `codes.json` 删除哈希，台账标记作废，提交推送。
- `list`：查看台账。
- 提醒：台账只在本机，建议备份；丢了不影响已发出的码，只是查不到谁是谁。

**已知限制（如实告知用户）：** 码在被作废前可被转发多人使用；清除网站数据或换手机后，装扮会丢，重新输入同一个码即可恢复 VIP；Safari 与主屏幕应用存储独立，需在主屏幕应用内激活。

## 二、用户资料与等级（所有人都有）

- **默认名字（已确认）：** 首次打开随机生成「形容词 + 动物」，如「机智的柯基」「快乐的熊猫」「淡定的水獭」（约 30 × 30 组合）。普通用户不能改；VIP / SVIP 可改（1–10 个字，去首尾空格和控制字符）。
- **经验值：** 每局 +20，每答对一个 +10。统计：局数、答对、跳过、单局最高分、玩过的主题、总时长。在结算时写入（`useGameController.ts` 里现有「一局结束 → markSeen 并 persist」的位置）。

## 三、会员等级：普通 / VIP / SVIP

用户追加要求：VIP 分 VIP 和 SVIP 两级，SVIP 的东西更多更好看；普通用户每类只有 1–3 个最基础的。

激活码带等级：`codes.json` 改为 `{ "version": 1, "vip": [哈希…], "svip": [哈希…] }`；工具命令 `new --tier vip|svip --to 张三`。VIP 用户再输入 SVIP 码即升级。名字旁显示等级标识：VIP 银色角标，SVIP 金色流光角标。

| 类别 | 普通 | VIP | SVIP |
| --- | --- | --- | --- |
| 名字 | 默认名字，不能改 | 可改名 | 可改名 + 名字渐变色（金色 / 彩虹 / 霓虹三选一） |
| 头像 | 3 个：🐣 🐶 🐱 | 普通 + 15 个（常见动物与角色） | 全部约 30 个 + 3 个 SVIP 专属（金底 🐉、星空底 🦄、霓虹底 🤖） |

| 称号 | 等级称号（玩出来的） | + 稀有、史诗称号 | + 传说称号（金色流光） |
| 徽章 | 可获得全部成就徽章，佩戴 1 个 | 佩戴 2 个 + 专属「奶茶支持者」 | 佩戴 3 个 + 专属「钻石会员」「嗨王之冠」 |

## 五、数据保存与备份

用户关心：更新版本、重新添加桌面后等级会不会丢。

- **应用内更新不丢数据：** Service Worker 更新只替换程序文件，localStorage 保留；存储版本升级时做迁移（v1 → v2 已规划，以后同理），绝不清空旧数据。
- **删除桌面图标会丢：** iOS 删除主屏幕应用时一并删除其数据。更新横幅（`src/components/UpdateBanner.tsx`）和「我的」页面加提示：「更新不会丢失数据，请不要删除桌面图标」。
- **持久存储：** 首次启动调用 `navigator.storage.persist()`（支持时），降低 iOS 在空间不足时清理数据的可能。
- **存档备份 / 恢复：**「我的」页面「备份存档」生成存档码（名字、经验、统计、成就徽章、装扮选择，JSON → 压缩 → Base64，前缀 `XHSAVE1-`），可复制保存到微信或备忘录；「恢复存档」粘贴即可。
  - 存档码带校验和，被改动或损坏时拒绝恢复，并提示原因。
  - **会员不进存档：** VIP / SVIP 恢复靠重新输入原激活码（仍需联网核对），避免通过分享存档共享会员；恢复存档后，超出当前会员等级的装扮自动退回可用的默认项。
  - 新逻辑放在 `src/profile/backup.ts`，带单元测试（往返一致、篡改检测、旧版本存档兼容）。

### 手动「检查更新」按钮（用户追加）

- 位置：首页底部（「已可离线使用」旁）和「我的」页面，显示当前版本号，如「版本 2026.11.26 · a1b2c3d」。
- 版本号：构建时由 Vite `define` 注入 `__APP_VERSION__`，取**最后一次修改程序的提交**（日期 · 短提交号），忽略只改 `public/vip/` 的提交。这样发激活码重新构建时程序文件逐字节不变，用户不会收到更新提示（已验证）。GitHub Actions 需 `fetch-depth: 0` 拉取完整历史。
- 点击后：
  1. 断网 → 提示「需要联网才能检查更新」；
  2. 调用 `registration.update()`（在 `src/platform/usePwa.ts` 里保存 `onRegisteredSW` 拿到的 registration），等待是否出现新的 Service Worker（最多约 10 秒）；
  3. 有新版本 → 提示「发现新版本，正在更新…」并调用现有的 `updateServiceWorker(true)` 刷新，数据保留；
  4. 没有新版本 → 提示「已是最新版本」；
  5. 检查失败或超时 → 提示「检查失败，请稍后再试」。
- 提示用一个轻量的 toast 组件（新增 `src/components/Toast.tsx`），游戏进行中不显示该按钮。
- 原有的自动检查（回到前台时）和「有新版本」横幅保留。

## 六、界面

- **首页顶部：** 资料条（头像 + 框 + 名字 + 称号 + 佩戴徽章），点击进入「我的」。
- **「我的」页面**（`#me`，与现有 `#debug` 同样的 hash 路由，见 `src/App.tsx` 的 `useHash`）：
  1. 资料卡预览（带装饰背景）；
  2. 等级进度条 + 下一级称号；统计数据；
  3. 分页选择器：头像 / 头像框 / 称号 / 徽章 / 装饰 / 配色——网格展示，未解锁的显示 🔒「VIP」或获得条件；
  4. VIP 区：状态（未开通 / 已开通，上次核对时间）、输入激活码、复用现有打赏弹窗（`src/components/Tip.tsx` 的 `TipDialog`），说明「打赏后把截图发给作者领取激活码」；
  5. VIP 可改名。
- **结算页：** 顶部加本局玩家条（头像 + 名字 + 称号）；获得新徽章 / 升级时提示「获得新徽章：十连对」「升级到 Lv3 比划学徒」。
- 免费用户点锁定项：弹出 VIP 说明 + 激活入口，不打扰游戏流程。
