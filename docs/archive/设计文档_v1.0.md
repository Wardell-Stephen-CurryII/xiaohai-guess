# 猜词派对（暂定名）------ iPhone / iPad 单机猜词游戏设计文档

> **文档版本：** v1.0\
> **日期：** 2026-11-25\
> **产品形态：** iPhone / iPad 主屏幕 Web App（PWA）\
> **核心原则：** 纯前端、离线优先、零后端、零账号费用、不上架 App Store

------------------------------------------------------------------------

## 1. 项目概述

### 1.1 产品目标

开发一款供朋友聚会时使用的单机猜词游戏。游戏过程中，手机横屏显示一个词语，持手机的人不能看屏幕，由朋友通过语言或动作进行提示。持手机的人根据猜测结果翻转手机：

-   **向下翻转：** 答对，得 1 分。
-   **向上翻转：** 答错 / 跳过，不得分。
-   **回到初始持机姿态：** 自动显示下一题。

游戏在限定时间内尽可能多地猜词，结束后展示成绩和本轮词语记录。

### 1.2 产品定位与边界

这是一个个人使用、朋友线下参与的轻量游戏，不需要账号体系、联网对战、排行榜或云端服务。

**本项目明确不做：**

-   不开发后端服务、API 服务或数据库服务器。
-   不做用户注册、登录和账号系统。
-   不做多人在线联机、实时同步或云端排行榜。
-   不上架 Apple App Store，不使用 TestFlight。
-   不购买 Apple Developer Program 会员。
-   第一版不开发原生 Swift / SwiftUI 客户端。

### 1.3 核心使用场景

1.  用户打开 iPhone 主屏幕上的游戏图标。
2.  选择词库类别和游戏时长。
3.  点击开始，按提示授权设备姿态传感器。
4.  手机横屏，屏幕显示一个大号词语。
5.  朋友向持机者描述词语，持机者进行猜测。
6.  持机者向下翻转表示答对，向上翻转表示答错 / 跳过。
7.  手机回到初始姿态后自动切换下一题。
8.  倒计时结束，展示本轮得分和答题记录。

## 2. 技术方案结论

### 2.1 推荐方案

采用 **React + TypeScript + Vite + PWA**。

将应用构建为静态网页，通过 HTTPS 部署到静态托管平台，再由 iPhone / iPad
的 Safari 添加到主屏幕。使用 Service Worker
缓存游戏所需的页面、词库、图标和音效，实现首次加载后离线运行。

### 2.2 技术选型

  模块         技术                     用途
  ------------ ------------------------ --------------------------------------------
  语言         TypeScript               业务逻辑与类型约束
  UI 框架      React                    页面和组件
  构建工具     Vite                     本地开发和生产构建
  PWA          vite-plugin-pwa          Web App Manifest、Service Worker、离线缓存
  样式         CSS / CSS Modules        横屏布局、动画和适配
  设备传感器   DeviceOrientationEvent   获取设备姿态角度
  备用传感器   DeviceMotionEvent        必要时读取加速度或旋转速度
  本地配置     localStorage             保存音效、时长、词库选择和校准参数
  词库         本地 JSON                保存游戏词语
  音效         本地 MP3 / WAV           答对、跳过、倒计时音效
  部署         Cloudflare Pages         免费 HTTPS 静态托管

第一版不需要 Tailwind、Dexie、FastAPI、Redis、PostgreSQL
或任何后端组件。界面样式使用普通 CSS 即可，避免引入不必要的依赖。

### 2.3 为什么选择 PWA

  对比项                      PWA                        SwiftUI 原生 App + 免费签名
  --------------------------- -------------------------- -----------------------------
  开发成本                    低                         相对较高
  是否需要 Apple 开发者会员   不需要                     不需要，但免费签名有期限
  安装方式                    Safari 添加到主屏幕        Xcode 安装
  7 天签名过期问题            没有                       有
  离线运行                    支持，需配置缓存           支持
  姿态传感器                  支持，但需授权并实机验证   原生支持更完整
  强制横屏                    iOS Safari 支持有限        原生支持
  App Store 上架              不需要                     不需要

**选择 PWA 的原因：**
本游戏主要使用屏幕显示、倒计时、本地词库、音效和姿态传感器，不依赖复杂系统
API。PWA 足以覆盖第一版需求，并避免原生 App 的签名维护成本。

### 2.4 费用与限制

-   Apple Developer Program：不需要购买。
-   App Store 上架费用：无。
-   后端服务器：无。
-   数据库：无。
-   Cloudflare
    Pages：使用免费额度即可满足小型静态应用的部署需求；免费额度和政策以平台当前规则为准。
-   域名：可直接使用平台提供的 `pages.dev` 子域名，不必购买域名。

因此，第一版可以做到 **基础使用成本为 0
元**。如果未来增加付费域名、云端服务或第三方 API，则另行评估。

## 3. 功能需求

### 3.1 首页

首页包含：

-   游戏名称和简单说明。
-   词库类别选择。
-   游戏时长选择：30 秒、60 秒、90 秒、120 秒。
-   音效开关。
-   开始游戏按钮。
-   传感器校准入口（首次使用或用户主动重新校准时出现）。

默认配置建议：

-   默认词库：全部类别。
-   默认时长：60 秒。
-   默认音效：开启。
-   默认操作：向下答对、向上答错 / 跳过。

### 3.2 词库

第一版内置以下类别，后续可以继续扩展：

-   动物
-   人物 / 名人
-   电影 / 电视剧
-   成语
-   食物
-   日常用品
-   体育运动
-   地点
-   游戏 / 动漫
-   网络热词

词库保存在本地 JSON 文件中，不需要数据库。每个词条至少包含唯一
ID、词语和类别。

建议数据结构：

``` json
{
  "version": 1,
  "categories": [
    {
      "id": "animals",
      "name": "动物",
      "words": [
        { "id": "animal-001", "text": "大熊猫" },
        { "id": "animal-002", "text": "长颈鹿" }
      ]
    },
    {
      "id": "movies",
      "name": "电影",
      "words": [
        { "id": "movie-001", "text": "泰坦尼克号" }
      ]
    }
  ]
}
```

词库要求：

-   游戏开始时，根据用户选择的类别合并词条。
-   每轮游戏对词条进行随机洗牌。
-   同一轮中，在所有词条被使用前不重复出题。
-   如果词库耗尽但游戏时间未结束，则重新洗牌；重新开始时尽量避免第一题与上一轮最后一题相同。
-   空词库或可用词条不足时，首页给出明确提示。
-   词库可直接通过修改 JSON 扩充，不需要修改游戏核心逻辑。

### 3.3 游戏界面

游戏界面采用横屏布局，核心元素包括：

-   当前词语：屏幕中央，大字号显示。
-   倒计时：顶部或角落固定显示。
-   当前得分：清晰显示答对数量。
-   操作提示：`向下翻转：答对`、`向上翻转：答错 / 跳过`。
-   暂停按钮。
-   传感器状态提示（仅调试或异常时展示）。

游戏中不显示多余信息，确保朋友能够快速看清词语。

### 3.4 操作规则

  用户动作                 游戏行为                     分数
  ------------------------ -------------------------- ------
  向下翻转并达到识别阈值   记录答对词语，进入下一题       +1
  向上翻转并达到识别阈值   记录跳过词语，进入下一题       +0
  回到初始姿态             允许下一次动作识别           不变
  时间结束                 停止识别，进入结算           不变
  手动暂停                 暂停倒计时和动作识别         不变

答对和跳过都只触发一次。一次翻转动作不能重复计分或连续跳过多题。

### 3.5 结算页面

展示：

-   本轮总得分（答对数量）。
-   答对数量。
-   答错 / 跳过数量。
-   本轮完成题目总数。
-   答对词语列表。
-   跳过词语列表。
-   再玩一局按钮。
-   返回首页按钮。

正确率计算：

`正确率 = 答对数量 /（答对数量 + 跳过数量）`

当本轮没有完成任何题目时，正确率显示为 0%，避免除以 0。

### 3.6 音效

使用项目内置的本地音频文件：

-   答对音效。
-   跳过音效。
-   倒计时结束提示音。
-   可选的最后 5 秒倒计时提示音。

音效必须允许关闭。音频播放需要在用户点击开始等明确交互后初始化，避免浏览器自动播放策略阻止声音。

## 4. 核心技术：手机姿态识别

### 4.1 技术目标

通过 iPhone / iPad
内置的陀螺仪和加速度计，判断用户是否完成指定方向的翻转动作：

-   向下翻转：答对。
-   向上翻转：答错 / 跳过。

这是整个项目最重要的技术验证点。**必须先在真实 iPhone
上验证传感器数据和方向映射，再大规模开发页面。**
桌面浏览器和模拟器不能替代真实设备测试。

### 4.2 浏览器 API

优先使用 `DeviceOrientationEvent`：

-   `beta`：设备绕 X 轴的姿态角变化。
-   `gamma`：设备绕 Y 轴的姿态角变化。
-   `alpha`：设备绕 Z 轴的姿态角变化。

必要时使用 `DeviceMotionEvent` 作为备用数据来源：

-   `accelerationIncludingGravity`：包含重力影响的加速度。
-   `rotationRate`：设备旋转速度。

注意：姿态角不是固定的地理方向值，而是相对于设备开始提供数据时的参考方向变化。因此不能简单地把某个固定的
`beta` 或 `gamma`
正负值写死为"答对"或"跳过"。需要基于实际持机姿态做校准，并在真实设备上确认方向。

### 4.3 权限要求

iOS 对设备运动和方向数据有权限控制。实现要求：

1.  游戏首页点击「开始游戏」后，由用户手势触发传感器权限请求。
2.  检查 `DeviceOrientationEvent.requestPermission` 是否存在。
3.  如果存在，则在点击事件中调用并处理 `granted` / `denied`。
4.  如果浏览器不需要显式请求，则直接尝试监听事件。
5.  监听 `deviceorientation` 后检查是否持续收到有效的 `beta` / `gamma`
    数据。
6.  如果方向数据不可用，再尝试 `devicemotion` 备用路径。
7.  如果用户拒绝权限或设备不支持，提供屏幕按钮操作作为降级方案。

传感器访问需要 HTTPS 安全上下文。Cloudflare Pages 默认提供 HTTPS。

### 4.4 校准设计

不同 iPhone
型号、横屏方向、用户持机方式可能造成姿态角轴向和正负方向不同，因此建议提供一次简短校准：

1.  提示用户横屏拿稳手机，保持游戏开始时的自然姿态。
2.  用户点击「记录初始姿态」，采集一小段稳定数据并计算中位数作为基准值。
3.  提示用户执行「向下翻转（答对）」动作，记录姿态变化。
4.  提示用户执行「向上翻转（跳过）」动作，记录姿态变化。
5.  根据两种动作中变化最明显的轴和方向，确定识别轴、正负方向和初始阈值。
6.  保存校准结果到 `localStorage`，后续启动时复用。
7.  用户可以在设置页重新校准。

校准参数应包含：

-   基准姿态。
-   识别轴。
-   答对方向。
-   跳过方向。
-   触发阈值。
-   回正阈值。

### 4.5 识别算法建议

第一版采用简单、可解释的阈值算法，不引入机器学习模型。

建议处理流程：

1.  监听姿态事件。
2.  对最近 5 个左右的样本做简单平滑，降低瞬时抖动。
3.  根据校准参数计算相对于初始姿态的有符号角度变化。
4.  角度达到触发阈值，并持续约 200--400ms，才确认一次动作。
5.  确认动作后立即锁定传感器触发，防止一次翻转重复计分。
6.  等待设备回到初始姿态附近（例如偏差小于约 10--15°）。
7.  回到中立区并稳定一小段时间后，显示下一题并重新允许触发。

建议初始调参范围（不是最终固定值）：

  参数                             初始建议 说明
  -------------- -------------------------- ----------------------
  动作触发角度                   约 35--50° 需要实机测试后调整
  动作保持时间                   200--400ms 过滤瞬时抖动
  回正角度                       约 10--15° 与触发阈值形成迟滞区
  平滑窗口                      约 5 个样本 降低传感器噪声
  动作冷却         一次动作完成前不重新触发 防止重复计分

**不要直接把上述数值当作所有设备的最终参数。**
应先记录真实设备的姿态数据，再确定阈值。

### 4.6 状态机

建议把姿态识别和游戏流程设计为明确状态，避免在多个 React
组件中散落条件判断。

``` text
HOME
  |
  v
REQUEST_PERMISSION
  |
  v
CALIBRATION
  |
  v
COUNTDOWN
  |
  v
PLAYING_READY
  |
  | 检测到向下 / 向上翻转
  v
ACTION_LOCKED
  |
  | 记录答对或跳过，更新分数
  v
WAIT_RETURN_TO_NEUTRAL
  |
  | 设备回到初始姿态并稳定
  v
PLAYING_READY
  |
  | 时间结束
  v
RESULT
```

补充状态：

-   `PAUSED`：用户主动暂停。
-   `SENSOR_ERROR`：传感器不可用，提示使用屏幕按钮。
-   `FINISHED`：时间结束，进入结算。

关键规则：

-   只有 `PLAYING_READY` 状态可以识别新动作。
-   `ACTION_LOCKED` 和 `WAIT_RETURN_TO_NEUTRAL` 状态禁止重复触发。
-   每次动作只更新一次答题记录。
-   游戏结束后移除或停用传感器监听。
-   页面进入后台时暂停游戏；重新回到前台后要求用户确认继续，避免后台计时和传感器数据异常。

### 4.7 屏幕按钮兜底

即使传感器识别正常，也建议保留两个不抢眼的备用按钮：

-   `答对`：等价于向下翻转。
-   `跳过`：等价于向上翻转。

传感器权限被拒绝、浏览器没有提供有效数据或用户不方便翻转手机时，游戏仍然可以继续。

### 5.4 横屏适配

游戏主体按横屏设计，但 iOS Safari / 主屏幕 Web App
对屏幕方向锁定的支持有限，不能把 `screen.orientation.lock('landscape')`
当作必然可用的能力。

处理方式：

-   游戏界面以横屏为主。
-   使用 CSS `@media (orientation: portrait)` 检测竖屏状态。
-   竖屏时显示「请将手机横向放置」的提示层。
-   横屏时显示正常游戏界面。
-   不依赖强制锁定屏幕方向。
-   iPad 同样适配横屏布局。

## 6. 游戏数据与本地存储

### 6.1 数据存储原则

第一版不需要数据库。所有词库、音效和图标随前端项目一起构建。

  数据             存储位置             是否需要持久化
  ---------------- -------------------- ----------------
  词库             本地 JSON 静态文件   随版本更新
  当前题目         React 状态           否
  当前得分         React 状态           否
  本轮答题记录     React 状态           否
  游戏时长偏好     localStorage         是
  音效开关         localStorage         是
  词库选择         localStorage         是
  传感器校准参数   localStorage         是

刷新页面后，本轮游戏可以丢失；第一版不要求保存历史战绩。

### 6.2 隐私

-   不采集用户身份信息。
-   不上传游戏记录。
-   不需要登录。
-   不需要分析 SDK。
-   传感器数据只在本机内存中处理，不上传服务器。
-   本地配置仅用于保存游戏偏好和校准参数。

## 8. 开发与部署方案

### 8.1 初始化项目

``` bash
npm create vite@latest guess-word -- --template react-ts

cd guess-word

npm install
```

第一版只需要 React、TypeScript、Vite 和 PWA
插件。不要提前引入后端、数据库或复杂状态管理库。

### 8.2 PWA 配置

在 `vite.config.ts` 中配置 `vite-plugin-pwa`：

``` ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import { VitePWA } from 'vite-plugin-pwa'

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'prompt',
      includeAssets: [
        'icons/apple-touch-icon.png'
      ],
      manifest: {
        name: '猜词派对',
        short_name: '猜词派对',
        description: '朋友聚会时玩的单机猜词游戏',
        start_url: '/',
        scope: '/',
        display: 'standalone',
        background_color: '#111827',
        theme_color: '#111827',
        icons: [
          {
            src: '/icons/icon-192.png',
            sizes: '192x192',
            type: 'image/png'
          },
          {
            src: '/icons/icon-512.png',
            sizes: '512x512',
            type: 'image/png'
          }
        ]
      },
      workbox: {
        globPatterns: [
          '**/*.{js,css,html,ico,png,svg,json,mp3,wav}'
        ]
      }
    })
  ]
})
```

`registerType: 'prompt'`
的目的，是让新版本更新可控，避免用户正在游戏时因为自动更新而突然刷新页面。可以在首页或一局游戏结束后提示用户更新。

在 `index.html` 中补充适合 iOS 主屏幕 Web App 的配置：

``` html
<meta name="viewport"
      content="width=device-width, initial-scale=1, viewport-fit=cover" />

<link rel="apple-touch-icon"
      href="/icons/apple-touch-icon.png" />

<meta name="apple-mobile-web-app-capable"
      content="yes" />

<meta name="apple-mobile-web-app-title"
      content="猜词派对" />
```

同时在 CSS 中适配安全区域：

``` css
.app {
  min-height: 100vh;
  min-height: 100dvh;
  padding:
    env(safe-area-inset-top)
    env(safe-area-inset-right)
    env(safe-area-inset-bottom)
    env(safe-area-inset-left);
}
```

以上配置需要在真实 iPhone / iPad
上验证，不应只以桌面浏览器预览作为验收依据。

### 8.3 构建

``` bash
npm run build
npm run preview
```

生产构建输出到 `dist/` 目录。先在本地检查构建结果，再部署。

### 8.4 部署到 Cloudflare Pages

1.  将项目提交到 GitHub 仓库。
2.  登录 Cloudflare，创建 Pages 项目并连接 GitHub 仓库。
3.  配置构建命令：`npm run build`。
4.  配置输出目录：`dist`。
5.  等待构建完成，获得 HTTPS 地址，例如 `https://your-app.pages.dev`。
6.  使用 iPhone / iPad 的 Safari 打开该 HTTPS 地址。

本项目是静态资源应用，不需要配置环境变量、数据库或服务器进程。

### 8.5 安装到 iPhone / iPad

1.  在 iPhone / iPad 上使用 Safari 打开部署地址。
2.  点击 Safari 的分享按钮。
3.  选择「添加到主屏幕」。
4.  如果出现「作为 Web App 打开」选项，将其开启。
5.  点击「添加」。
6.  返回主屏幕，点击新生成的游戏图标启动。

安装后是主屏幕 Web App，不是通过 App Store 安装的原生 IPA。

### 8.6 离线运行验证

首次访问和安装需要网络。完成首次加载、Service Worker
激活并确认静态资源缓存后，再进行离线测试：

1.  正常联网打开应用。
2.  等待首页、词库、音效和图标全部加载。
3.  关闭应用，再重新从主屏幕图标打开。
4.  开启飞行模式。
5.  再次打开应用，检查首页和游戏能否正常运行。
6.  测试开始游戏、翻转识别、倒计时、音效和结算。

注意：离线能力依赖 Service Worker
缓存成功。系统清理网站数据、用户手动删除 Web App
或缓存被清除后，可能需要重新联网加载。

## 9. 测试计划

### 9.1 第一优先级：真实设备姿态识别验证

先开发一个最小传感器测试页面，只显示：

-   当前 `beta` / `gamma` 值。
-   校准后的角度差。
-   当前识别状态。
-   当前识别结果。
-   权限状态。

测试步骤：

1.  使用真实 iPhone 的 Safari 打开 HTTPS 测试页面。
2.  点击按钮申请传感器权限。
3.  手机横屏，记录初始姿态。
4.  执行向下翻转，观察数据变化方向。
5.  回正。
6.  执行向上翻转，观察数据变化方向。
7.  分别测试左手和右手持机。
8.  测试不同横屏方向。
9.  记录数据并调整阈值。
10. 确认正常拿稳、轻微晃动不会误触发。

**传感器测试通过后，再进入完整游戏页面开发。**

### 9.2 功能测试

  测试项           预期结果
  ---------------- --------------------------
  首页选择词库     只从已选类别出题
  随机出题         本轮词库耗尽前不重复
  向下翻转         答对数量增加 1
  向上翻转         跳过数量增加 1
  单次翻转         只触发一次
  回正             可以识别下一次动作
  倒计时           到 0 后停止游戏
  暂停 / 继续      暂停期间不扣除游戏时间
  音效关闭         不播放音效
  传感器拒绝授权   可以使用屏幕按钮继续
  页面切到后台     暂停游戏，返回后确认继续
  再玩一局         重新洗牌并重置分数

### 9.3 PWA 与离线测试

-   Safari 可以正常打开部署地址。
-   可以添加到 iPhone / iPad 主屏幕。
-   主屏幕图标显示正确。
-   从图标启动时呈现独立 Web App 界面。
-   横屏布局正常。

-   词库、音效、图标均可离线读取。
-   新版本发布后，可以在安全时机提示更新。

### 9.4 设备测试

至少在一台真实 iPhone 上完成完整测试。条件允许时，再测试一台 iPad。

不要仅依赖桌面 Chrome
的设备模拟模式验证姿态传感器，因为模拟器不一定提供真实的陀螺仪和加速度计数据。

## 10. 风险与应对

  -------------------------------------------------------------------------------------------
  风险                       影响                    应对方式
  -------------------------- ----------------------- ----------------------------------------
  iOS 传感器权限被拒绝       无法翻转识别            提供屏幕按钮兜底

  横屏时姿态轴向不同         答对 / 跳过方向错误     首次校准，实机验证

  手持抖动导致误判           重复计分                平滑、保持时间、迟滞区、状态锁

  iOS 不支持强制横屏         竖屏体验不好            竖屏提示层，不依赖锁定 API

  页面进入后台后计时不准确   游戏时间异常            监听 `visibilitychange` 并暂停

  音效自动播放被拦截         没有声音                用户点击开始后初始化音频

  缓存未完成                 离线无法启动            首次加载后提示缓存完成，并执行断网验收

  iOS 清理网站数据           本地缓存丢失            保持资源轻量，必要时重新联网加载

  不同设备识别效果不同       用户体验不一致          保存校准参数，提供重新校准入口
  -------------------------------------------------------------------------------------------

### 10.1 关于横屏的特别说明

iOS Safari 对 Web App 的屏幕方向锁定支持有限。项目不应依赖
`screen.orientation.lock('landscape')`
一定成功。正确做法是设计横屏游戏布局，并在竖屏时显示旋转提示。

### 10.2 关于离线的特别说明

PWA 并不意味着第一次打开就能无网络运行。需要先通过 HTTPS 加载应用，并让
Service Worker 成功缓存所有必要资源。完成后才可离线使用。

## 11. 开发里程碑

建议按以下顺序开发，先验证高风险部分，再完善体验。

### 阶段 1：传感器技术验证（最高优先级）

交付内容：

-   最小 React 页面。
-   申请 DeviceOrientationEvent 权限。
-   显示 beta / gamma 实时数据。
-   记录初始姿态。
-   分别识别向下和向上翻转。
-   验证回正逻辑。
-   确定第一版阈值。

验收标准：

-   真实 iPhone 上能稳定读取姿态数据。
-   能区分两种方向。
-   一次动作只触发一次。
-   普通轻微晃动不会频繁误判。
-   权限失败时能识别并给出提示。

### 阶段 2：核心游戏闭环

交付内容：

-   首页。
-   词库读取和随机洗牌。
-   倒计时。
-   答对 / 跳过。
-   下一题切换。
-   分数统计。
-   结算页面。
-   屏幕按钮兜底。

验收标准：不依赖后端即可完成一整局游戏。

### 阶段 3：体验完善

交付内容：

-   横屏布局。
-   竖屏提示。
-   音效。
-   暂停 / 继续。
-   校准入口。
-   本地偏好设置。
-   词库扩充。

### 阶段 4：PWA 与离线部署

交付内容：

-   Web App Manifest。
-   Service Worker。
-   静态资源预缓存。
-   iOS 图标和启动配置。
-   Cloudflare Pages 部署。
-   iPhone / iPad 主屏幕安装。

验收标准：安装后断网仍可完成完整游戏。

### 阶段 5：真实场景验收

找朋友进行实际游戏测试，重点观察：

-   朋友能否快速看清词语。
-   翻转动作是否自然。
-   答对 / 跳过识别是否准确。
-   识别是否过于灵敏或迟钝。
-   倒计时和音效是否影响体验。
-   连续玩多局是否稳定。

## 13. 给 Codex / Claude Code 的实施要求

建议将本文档作为项目的开发依据，并按里程碑逐步实现。

开发约束：

1.  **先做传感器 PoC，不要先做完整 UI。** 第一阶段必须在真实 iPhone
    上验证。
2.  不要引入后端、数据库、登录、云同步或在线排行榜。
3.  不要为了架构完整而过度设计，第一版保持简单。
4.  姿态识别逻辑独立封装，不要写在页面组件中。
5.  游戏流程使用明确状态管理，确保一次动作只触发一次。
6.  所有游戏资源（词库、音效、图标）随前端静态构建。
7.  必须支持传感器不可用时的触屏操作。
8.  必须支持 Service Worker 离线缓存。
9.  必须在真实 iPhone 上测试，不能只用桌面模拟器验收。
10. 每完成一个阶段先运行测试并说明结果，再继续下一阶段。

**建议第一条开发任务：** 创建 Vite + React + TypeScript
项目，只实现一个传感器调试页面。在真实 iPhone 上通过 HTTPS
打开，申请权限并显示姿态数据，完成向下 /
向上翻转方向验证和校准。通过后再开发游戏主体。
